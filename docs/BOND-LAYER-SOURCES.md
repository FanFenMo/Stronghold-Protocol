## 层数产生与结算的统一公式

`L` 是目标盟约当前层数，`n` 是这次事件计算出的层数，`C` 是该特质每场每个盟约的上限，`U` 是该特质实例已消耗的上限额度，`e` 是魔王等钩子的额外层数。

`ΔL = min(999-L, max(0, floor(n)))`，`L新 = L + ΔL`。战斗特质有上限时，先取 `n0=min(floor(n),max(0,C-U))`，再由钩子追加 `e`，实际 `ΔL=min(999-L,n0+e)`。仅在实际有增加时消耗额度；魔王额外层数不占来源特质的 `C`，所以不能简单把最终累计层数也限制到 `C`。

表中的累计公式以目标一直激活、条件一直满足、没有其他重触发及额外层数为前提。按人数、资金、刷新数产生层数的公式，在事件触发时取值；多个副本各自触发，最后分别经过 999 层封顶。

战斗增量立刻写入战斗层数副本，结算后进入玩家持久层数。普通作战可叠层；联防、最终攻势、隐秘核心默认禁止战斗内叠层。未激活盟约仍保留旧层数；明确无需激活的休整期来源可提前叠层。调和、协防干员、独行、绝技隐藏层数，但仍接受层数来源，参与已激活盟约总层数统计。

获得时特质在投资人激活后重复 2 次，投资人达到 100 层后重复 3 次。身前干员因战斗特质加层时，魔王普通额外 +1、精锐额外 +2；阿戈尔吞噬不直接叠层，魔王不会从吞噬生成额外层数；魔王不加成 `reason='bond'` 的层数。

## 查阅和维护

先在 [BOND-FORMULAS.md](BOND-FORMULAS.md) 找到盟约 ID 和战斗加成，再从本文件查产生 `L` 的来源、普通/精锐差别、限制。特质 ID 指向 `data/garrisons.json`；黑板数字最终由其 `effectKey` 对应的处理器解释，不能只把描述中的每个数字都乘起来。

本次只增加参考文档，没有修改玩法、生成数据或界面。后续调整参数时，需要同时更新公式和层数对照，尤其是概率封顶、取整、特质授予上限与按层增益。
